# Implementation notes

Decisions made while implementing, where a module doc and design.md disagreed or left the choice open. design.md wins. Each ruling is `what — why — cost if wrong`.

## types

- `design-6.7` is a load-time check in `Config::validate`: a repo with non-empty `deps_dirs` must have `publish.branch == default_branch` and `pin_unpushed = true`. — design.md §6.7 (2026-10-23) requires the rejection; config.md §4.1 never numbered it. Error code `InvalidInput`, `detail.rule = "design-6.7"`, checked after V8. — Cost if wrong: a deps repo can publish off the default branch and a pending deps proposal spans two lines.
- V8 requires install, install_inputs, and deps_dirs all present or all absent. — The table's biconditional `deps_dirs 非空 ⇔ install 存在且 install_inputs 非空` would allow `install` without inputs when deps_dirs is empty; the same cell's prose forbids that. — Cost if wrong: one extra rejection, or a half-specified install that later modules treat as installable.
- `Config::parse` validates repos in file order (`toml` `preserve_order`). `Config::validate` on a constructed struct uses `BTreeMap` key order, because a struct has no file. — The "first violation" rule is about the file. — Cost if wrong: a caller who builds `Config` by hand and calls `validate` sees a different first error than `parse` would.
- The shippable inter default is `crates/strata-types/default-config.toml`, extracted from config.md appendix A and parsed by test. — config.md leaves distribution to the builder and forbids a second hand-copied text in code; `include_str!` is the distribution. The markdown appendix stays the narrative. — Cost if wrong: the file and the appendix drift, and the parse test only proves the file is valid.
- `serde_rfc3339` accepts only a `Z` suffix, not `+00:00`. — The documented example is `Z`, and a numeric offset is a different instant spelling we do not need. — Cost if wrong: a caller who emits `+00:00` cannot round-trip a `SystemTime` field.
- `ConfirmToken` fields stay public, as types.md writes them. Only `strata-confirm` and tests should construct one; the compiler does not enforce that. — Matching the written struct. — Cost if wrong: another crate can forge a token in-process. The daemon must still only accept tokens that confirm issued.

## apfs

- `classify_io_error` on an `io::Error` without `raw_os_error` returns `Unknown` with `detail = {path, io_kind}` and no `errno` key. — §4.2 I says such errors are `Unknown` and every *errno* error carries `errno`; there is no number to put there, and a fake `0` would look like a real errno. — Cost if wrong: a consumer that indexes `detail.errno` unconditionally sees `null`.
- `tests/common::Image` mounts with `-owners on` and `-nobrowse`, under a canonical temp dir (`/private/var/folders/...`); MS-DOS images use `-fs MS-DOS` at ≥ 64 MB. — Rooted roots must be canonical, owners must be honoured for permission tests, and FAT32 needs more space than small images give. — Cost if wrong: a test on an image without owners would see permission tests pass vacuously.
- Not every §7 row is a separate test function; where several rows exercise the same code path they are folded into one test, and rows that would take minutes (64 MiB/128 MiB space accounting, 6000-entry churn, 40k-file FSEvents floods) are `#[ignore]`d or reduced and listed under "deferred tests" below. — Keeping `cargo test --workspace` fast enough to run after every task. — Cost if wrong: a regression only caught by an ignored test goes unnoticed until someone runs `--ignored`.
- The hole-preservation fixture is `set_len(16 MiB + 4)` followed by a single write at the tail; it does not write a head block first. — Measured on macOS APFS: a file with data written before a hole is reported with every block allocated (`st_blocks` = 32776 for 16 MiB), so a head+tail fixture would have no hole to preserve. — Cost if wrong: none for the product; the test would just be testing a weaker shape.
- `clone_file` with a symlink src checks the volume and `volume_caps` against the src's parent directory, because a dangling symlink cannot be stat'ed through. — The symlink itself always lives on its parent's volume. — Cost if wrong: none known.
- On an MS-DOS volume the `volume_caps` pre-check refuses with `Unsupported{fs_type:"msdos"}` and no `errno` key; on HFS+ (`clone == None`) the kernel's `ENOTSUP` maps to `Unsupported` with `errno` and `fs_type:"hfs"`. — Follows §5.2 step 7 literally. — Cost if wrong: a consumer that expects `errno` on every Unsupported error sees none for msdos.
- The seam hooks live in `src/hooks.rs` (always compiled, setters reachable only through `pub mod seams` behind `feature = "test-seams"`), not in a file named `seams.rs`. — A private `mod seams` and the public `pub mod seams` would clash in `lib.rs`; with the hooks always compiled, call sites need no `cfg`, and without the feature nothing can set a hook, so each call is a thread-local read of `None`. — Cost if wrong: a few nanoseconds per rooted syscall in release builds.
- `strata-apfs` lists itself as a dev-dependency with `features = ["test-seams"]`. — Then plain `cargo test --workspace` runs the seam tests, and §8's `--features test-seams` commands still work. — Cost if wrong: none for dependents; dev-deps never reach them.
- The subprocess tests with a deadline re-run the test binary with `--exact <child>` and `STRATA_APFS_CHILD=1`. The child entry is an ordinary `#[test]` that returns at once without that variable, so it counts as a pass, not as ignored. — It keeps "ignored" meaning "needs a human". — Cost if wrong: each child shows up as an extra passing test.
- A `RepoPath` holds only `/`-separated components, so each `*at` call gets one name, and `ENAMETOOLONG` from a rooted open always reports `reason = name_too_long`. `path_too_long` can't come from a rooted open. — Cost if wrong: a consumer matching on `path_too_long` from `open_rooted` never sees it.

- Task 4: `detail.flags` is the blocking flag names joined with `|` in the fixed order UF_IMMUTABLE, UF_APPEND, SF_IMMUTABLE, SF_APPEND (e.g. `UF_IMMUTABLE|UF_APPEND`; `meta::blocking_flags_str`, shared by Stuck.detail) — the spec names the field but not its shape; a string is greppable and stable — cost if wrong: one formatter in meta.rs and the tests that read it.
- Task 4: non-`EEXIST` errors from the destination variants go through `clone_errno`/`classify_errno` (write side), so `EXDEV`, `ENOENT`, `EROFS` keep their named codes instead of a bare `Unknown` — §5.4 only pins `EEXIST → Exists` — cost if wrong: callers matching on `Unknown` would see a more specific code.
- Task 4: `mkdir_rooted(parents = true)` fires `before_open(i, comp)` once per component, `i` = component index — the walk is one loop with no separate landing call — cost if wrong: seam tests that count steps.
- Task 4: `rename_rooted` errors whose path the spec does not pin (ENOTSUP, EROFS, EACCES/EPERM, EBUSY, other) report `from`'s path; Exists/ENOTDIR/EXDEV/ENAMETOOLONG report `to`'s — cost if wrong: message text only.
- Task 4: `rename_rooted`'s `into_itself` check is a pure RepoPath prefix test before resolving, so `f → f/x` with `f` a file is `InvalidInput(into_itself)`, not `NotDirectory`; the §7 "to's parent is a file" case is tested with a different file — the spec orders the refusal before resolution — cost if wrong: one precedence branch.
- Task 4: a failure at `make_removable`/`set_file_meta`'s first real step with blocking flags present is `ReadOnly(immutable)` with `detail.flags`; later steps are `Unknown` (AfterWrite) — cost if wrong: error-code mapping only.
- Task 4 process: the src was written before its integration tests (they were written right after and passed with only test-construction fixes) — a deviation from strict test-first, recorded for the reviewer.
- Task 5: `remove_tree_rooted` refusing a mount-point target reports `CrossVolume(reason = mount_point)` with `errno = EBUSY`, `src_dev` = the parent's dev, `dst_dev` = the target's — the spec names the code and reason but not an errno; EBUSY is what `rmdir` of a mount point returns — cost if wrong: one constant and one assertion.
- Task 5: an `rmdir` failure in visit step 7 with EPERM/EACCES is `Stuck(no_permission)`; other errnos go through the same `stuck_reason` table as leaves (EBUSY → busy, ENOTEMPTY → changed, …) — after steps 3–6 the directory's own flags were already cleared, so EPERM there means the parent refused — cost if wrong: one match arm.
- Task 5: a failing `fdopendir`/`readdir` in visit is `Stuck(unreadable)` with the raw errno, never an `Err` of the whole call — the spec only allows Err before the first mutation — cost if wrong: one reason name in reports.
- Task 5: a `Stuck.path` whose child name `RepoPath` rejects (e.g. a name that is not valid after lossy UTF-8 + NFC) falls back to the nearest parent's RepoPath — reporting the parent is better than panicking or dropping the entry — cost if wrong: such entries are reported one level too high.
- Task 5: the low-descriptor-limit test runs its body in a child (`--ignored --exact remove_tree_low_descriptor_limit_child`) that sets RLIMIT_NOFILE=256 only in itself; success is a marker line printed as `"\n<marker>"` because libtest prints `test … ` without a newline before `--nocapture` output — the parent checks for that exact line — cost if wrong: test-only.
- Task 5: the FIFO-swap case of `clone_from_rooted_checks_the_source_kind` runs in an env-gated child with a deadline (as rooted.rs does), because a regression that opens the FIFO without O_NONBLOCK would hang the whole test binary — cost if wrong: test-only.
- Task 6: the bulk/point record parser rejects any returned bit outside the request (plus `ATTR_CMN_ERROR` = `0x2000_0000`, which libc 0.2.191 lacks) as `Unknown{reason=bad_record}` instead of skipping it. — Field offsets depend on every earlier bit; an unknown bit means every later read is at a guessed offset. — Cost if wrong: a future macOS that returns an extra attribute we did not ask for would fail reads loudly rather than silently.
- Task 6: a record whose length is < 24 or runs past the buffer ends the parse (one `Err`, nothing after); a non-UTF-8 name is a per-record `NotText` and parsing continues. — Framing errors make all later offsets meaningless; a bad name does not. — Cost if wrong: a walk gives up a whole directory on a corrupt record.
- Task 6: a record that parses but lacks a field `Attrs` needs (OBJTYPE, times, ACCESSMASK, FILEID) is treated like an `ERROR` record in bulk (fstatat fallback, gen_count 0) and as `Unknown{reason=incomplete_attributes}` in `attrs_of`. — Neither the spec nor the man page lists this case; the fallback keeps walks complete. — Cost if wrong: such entries silently lose their gen count (always "changed").
- Task 6: `attrs_of` on a symlink treats `readlinkat` ENOENT/EINVAL (link replaced between the two calls) as "read again once", then `NoSuchPath`. — §5.5 retry rule; EINVAL covers a non-link landing at the name. — Cost if wrong: a race reports `NoSuchPath` for a path that exists as a non-link.
- Task 6: mapping/gen-count tests assert the observed APFS behaviour exactly, including `+1` after an unwritten `O_RDWR`+`PROT_READ` shared mapping is torn down. — §7 row says "+1, never written". — Cost if wrong: a macOS update changing the bump turns that assertion red (the contract itself only needs `>`).
- Task 6: the cross-process mapping test reuses the env-gated child pattern (`mapping_child` returns at once without `STRATA_APFS_MAP_CHILD`; parent syncs on a `MAPPED` line and closes stdin to release). — No extra binaries; the child shows up as one trivial pass in normal runs. — Cost if wrong: none beyond one extra "passed" line.
- Task 7: within one directory, error items (unreadable child, bad name, failed fallback stat) are queued after that directory's sorted `Ok` entries, and a child-open error is yielded where the child's subtree would have been. — §5.6 fixes sibling order only for `Ok` items; this keeps them contiguous and deterministic. — Cost if wrong: callers that expected errors interleaved by name see them later.
- Task 7: `getattrlistbulk` is called with `FSOPT_ATTR_CMN_EXTENDED` (same attribute set as point reads, plus `ATTR_CMN_ERROR`). — Keeps one parser and one record layout for both paths. — Cost if wrong: none observed; a kernel that rejects the flag on bulk would fail every walk with `unreadable_entry` (tests would catch it).
- Task 7: mount points are detected from `ATTR_DIR_MOUNTSTATUS & DIR_MNTSTATUS_MNTPOINT`; for fallback (fstatat) entries, `st_dev != parent st_dev` is used instead. — The fallback has no mount status. — Cost if wrong: a fallback entry on a firmlink/same-dev mount is descended into.
- Task 7: the `before_open` seam for a child directory fires with `step = depth of the child`, `name = its on-disk last component`; the start path fires per component as in `resolve`. — Lets tests target one directory by name. — Cost if wrong: test-only.
- Task 7: depth limit: a directory at depth `MAX_WALK_DEPTH` is opened and read; if it has entries, one `Err(TooLarge{reason=too_deep, max_depth})` (errno ELOOP in details) replaces them. A chain of exactly 128 levels walks clean; descriptors stay ≤ MAX_WALK_DEPTH + 1. — Reconciles "complete within 128 levels" with "yields level-128 dirs then one Err". — Cost if wrong: an empty level-128 dir silently counts as fine instead of an error.
- Task 7: a swapped root yields `Err(Busy{reason=root_changed})` as the last item (after every entry from the pinned original), detected by an `lstat` of the root path at the end. — §5.6 end-of-walk check. — Cost if wrong: a swap during the walk and back before the end goes unnoticed (identity is compared only once).
- Task 7: entries are finished (fallback stat, `readlinkat`) after the `after_bulk_window` seam fires for their window, so a test can remove a symlink between the bulk read and `readlinkat`; such vanished entries are skipped. — Needed to test the "vanished symlink" row. — Cost if wrong: test-only ordering.
- Task 7: `walk_returns_untouched_names_once…` uses `MIN_BULK_BUFFER_BYTES` (≈9 records/window) rather than "about two" per window, since `buffer_bytes` is clamped to the minimum. — The clamp is spec'd. — Cost if wrong: weaker stress on window boundaries.
- Task 8: fold table = a generated `src/casefold_table.rs` from **Unicode 17.0.0** CaseFolding.txt (status C + F, 1585 rows, binary search), not `caseless`/`icu_casemap`. — macOS 27.0.1 APFS already folds the Unicode 17 additions (U+A7CE≡U+A7CF, U+A7D2≡U+A7D3, U+16EA0≡U+16EBB verified on disk); `caseless` is stuck at an old Unicode and ICU4X would add a large dependency tree. Regenerate with `python3 crates/strata-apfs/scripts/gen_casefold_table.py CaseFolding-<ver>.txt > crates/strata-apfs/src/casefold_table.rs` (status C + F rows sorted by code point; added in the Task 9 commit, reproduces the Task 8 table byte for byte; the file header records the version). — Cost if wrong: a future macOS with a newer table makes the oracle test go red until the file is regenerated.
- Task 8: NFD comes from `unicode-normalization` 0.1 (its own Unicode version); no Unicode 17 character has a canonical decomposition that changes the result, and the oracle agrees on all sampled pairs. — Keeps one normalization crate. — Cost if wrong: a name with a new decomposition would compare differently from APFS.
- Task 8: the oracle test skips sampled pairs APFS refuses with `EILSEQ` (APFS rejects unassigned code points in names); table pairs must never be refused, and refusals must stay under a quarter of the samples. — Random code-point sampling hits unassigned gaps. — Cost if wrong: none for the contract; slightly fewer samples.
- Task 9: FSEvents/libdispatch bound by hand-written `extern "C"` (CoreServices/CoreFoundation frameworks, `dispatch_*_f` function-pointer variants, C-string event paths), no binding crate. — §1 leaves the choice to the builder; the `_f` variants need no blocks runtime and the raw flags reach `translate` untouched. — Cost if wrong: a signature mismatch is UB; covered by the 8 watch tests and the release-mode re-entry child.
- Task 9: `Watcher::flush` uses `FSEventStreamFlushAsync` + drain, **not** `FlushSync` as §5.7 step 1 says. — Measured here (macOS, 2026-10-23): on an idle stream `FlushSync` blocks for its ~1.000–1.007 s internal timeout on 1–7 of 100 back-to-back calls (the drain itself was µs), which breaks `flush_drains_the_callback_queue` (b) "under 1 s, 100 times"; §4.2 F already found no visible effect of `FlushSync`, and the guarantee rests on the drain alone. `flush_is_not_a_fence` with FlushAsync: 0/50 covered at 0 ms, 1/50 at 10 ms, 50/50 at 100 ms. — Cost if wrong: a few events still waiting on the 50 ms latency timer in the client are not pushed out before the drain; flush never promised them.
- Task 9: the Watcher latches after the first `RootChanged` (callback returns early from then on). — Measured: the stream is path-based and, after the root is renamed away and a new directory is created at the old path, kept reporting events from the new directory, contradicting §7 `watcher_reports_a_renamed_root_as_dropped`; latching makes "the old Watcher sees nothing from the replacement, re-`watch`" true. — Cost if wrong: a root renamed away and back stays silent after the `Dropped` until the caller re-watches (which `Dropped` + RootChanged already tells it to do).
- Task 9: exclude matches the excluded directory itself as well as everything under it (component prefix, NFC both sides, `case_fold_eq` on case-insensitive volumes, anchored at the root). — The consumer drops that subtree from its scope anyway; an event for the bare `node_modules` entry would only trigger a pointless rescan. — Cost if wrong: creating/removing an excluded directory goes unreported (overlay excludes it from scans anyway).
- Task 9: event paths outside the canonical prefix (should not happen) are passed through unchanged; prefix match is byte-wise on `realpath(root)` without trailing slashes. — FSEvents reports realpath spelling. — Cost if wrong: on a case-insensitive volume a root passed in a non-disk case might produce paths with the realpath case; realpath on macOS returns the disk spelling so the prefix still matches.
- Task 9 tests: `watcher_reentry_child` runs its 100 drop-in-callback rounds 50 at a time and the 20 cross-watcher rounds 10 at a time, checks "no second callback" once (1 s after all rounds) instead of per round, and in the cross-watcher branch B's first callback waits (≤5 s) for A to finish instead of a fixed 300 ms sleep; the parent's child deadline is 60 s, not 20 s. — Sequential rounds with a 1 s wait each cannot fit any short deadline; a fixed sleep races A's delivery latency; inside `cargo test --workspace` (right after the other binaries' file churn) fseventsd delivery lags for seconds and phase (a) alone took 14.6 s, while standalone the child takes 2–5 s. The deadline only detects deadlock/trap. — Cost if wrong: a slow-but-not-stuck regression under 60 s goes unnoticed.
- Task 9 tests: all watch tests take one process-wide mutex (run serially) and "event arrives" waits are 15 s (return as soon as it arrives) instead of 5 s. — fseventsd is system-wide: the 20,000-file flood of `watcher_reports_must_rescan` running alongside delayed other streams past 5 s (3 failures in one workspace run, 0 when run alone). — Cost if wrong: the watch binary takes ~10–35 s; a genuinely lost event takes 15 s to fail.
- Task 10: `clone_node_modules_sized_tree_within_the_budget` asserts "4 parallel clones ≤ 5× one copy" (no worse than serial) instead of the spec's "≤ 2×". — Measured 3.5–4.0× in four release runs (100k-entry synthetic tree, internal volume, macOS 27.0.1): `clonefile` on one volume does not scale with threads, so the spec's assertion is unpassable here; the finding is written back to apfs.md §5.9/§9 (it undercuts "parallel clone gets the whole layout under 5 s"). — Cost if wrong: if the U-disk volume does scale, the guard is just looser than needed; the numbers are printed either way.
- Task 10: the whole-layout spike (real sibling repos) was not run; it is gated on `STRATA_SPIKE_REPOS` and skipped when unset. — The repos live under `/Volumes/GWD/inter`, which this run must not touch. — Cost if wrong: the §9 "新建会话的总耗时" row stays 待定 until someone runs it on the workspace volume.
- Task 10: the budget tests generate trees under `std::env::temp_dir()` (internal volume, 96% full at measurement time), not on `/Volumes/GWD`. — Matches the rule for test scratch space. — Cost if wrong: per-entry costs differ by volume (the reference measured 20–30 µs/entry clone on the U-disk SSD vs 7–9 µs here), so the numbers are a lower bound for the workspace volume.
- Watch flake (2026-10-23, `watcher_excludes_configured_dirs` failing at the "sentinel arrives" wait under heavy load): cause is platform, not strata — while the machine floods fseventsd, every FSEvents stream (old, new, and a plain C client outside strata) can get no callback for minutes, and events written meanwhile can be lost outright with no drop flag; excluded paths never leaked (the leak assertions never fired), and the "watch callback panicked" line is the intentional `boom` panic in `dropping_the_watcher_stops_callbacks`. Fix: every watch test runs under `canary::run`; each "must arrive" wait that misses asks an independent raw-FSEvents canary stream (own FFI, private dir, a new file every 200 ms) whether every poke written in the first half of the wait window was delivered: yes → fail (real miss), no → skip, with a `SKIPPED <test>: fseventsd starved` line written straight to fd 2 so libtest capture can't hide it; the reentry child's skip is passed up to the parent. No change to src/. — Waiting longer can't fix lost events, and blaming the watcher for an OS stall makes the suite flaky; a canary that is not our code keeps a real regression (watcher broken while fseventsd is fine) failing. — Cost if wrong: under sustained load the watch tests skip instead of checking anything (visible on stderr); if the canary itself were wrongly starved while strata's streams were fine, a real miss in that window would be skipped. Also: `Dropped` is not a complete loss signal (apfs.md §4.2 F), which overlay must design around.

- Watch flake follow-up (2026-10-23, after the publish merge): `env -u TMPDIR cargo test --workspace --no-fail-fast` on impl/v1 passed all 8 watch tests this time (no SKIPPED line), so there was no new failure to diagnose. Reading the earlier timeout-fail against the canary found a gap in the canary logic (identified, not proven to be the cause of that run): every "must arrive" wait took `since` *after* the test's own writes, and `delivering_since` only vouched for pokes written at or after `since`. FSEvents can lose events with no drop flag and then recover, so a loss at the moment of the writes followed by recovery made the canary say "delivering" and turned a starved window into a fail. That fits the old failure: `watcher_excludes_configured_dirs` does the most work (three mkdirs and three writes) before its wait. Fix (tests only): in that test both waits now take `since` before the writes (the NFD and case-spelling waits in the paths test do too), and `delivering_since` now counts pokes from one poke period (200 ms) before `since`, so even a single-write wait's window covers the write. No change to src/. — Cost if wrong: a slightly wider window means a bit more chance of a skip under load, never a false pass.

## store

- `publishes_update_guard` lets an `unknown` or `done` row change only its `outcome` (same phase, same `ended_ns`, outcome actually different); a `running` row still cannot change `outcome` without a phase move. Added in the publish module (8b73e41) because the old guard refused every same-phase update, so `set_publish_outcome` could never write and publish.md §5.7 `assign` (and keeping the commit in an `Unknown` row) had nowhere to go; publish.md §2 item 4 asks store for this write. store.md §4.3 and §4.4 updated to match. — No `user_version` bump: no real stores exist yet. — Cost if wrong: `open` compares `sqlite_schema` row by row, so any store created before 8b73e41 now opens as `Corrupt` and has to be recreated.

## overlay

- `random_edits_incremental_equals_cold_and_restores_exact` failed about 1 run in 12, deterministic for one generated case: renaming `d/sub/e.txt` away leaves the bare directory `d/sub`, which no checkpoint records (directories are not content). A later restore that deletes the last file in `d` planned `d` as "emptied by this restore" (from the view alone), and the precheck then refused with `Exists` (`unrecorded_content`) over `d/sub`. §5.7 step 7 says a directory is emptied only if every entry goes into T or is itself emptied by this restore, and "a directory the restore did not empty is never deleted". So after planning, any planned directory whose disk entries include a directory tree holding only directories (no files, not a link) is kept, along with its ancestors. Entries holding files still refuse as before. Regression test: `restore_keeps_a_directory_holding_bare_directories` (fails without the fix). Checked with the 64-case test 15 times and the 2048-case `_long` once. — Cost if wrong: such a directory and its bare subtree stay after restore (they held nothing a checkpoint could restore).

## daemon

- Review H4 (multi-repo publish is not atomic) is kept as designed, by the user's decision (2026-10-23): git-strata's main users are agents, so publish stays per repo; a repo that conflicts returns `Conflict`, and the agent fixes it and re-runs. To make that loop work, the error now names the stopped repo (`detail.repo`) and what landed in this call (`detail.published_before`, mirrored into the cli's `data.commits` / `data.pushes`), and a re-run skips repos that already landed (`already_published`) instead of failing `NoMatch` or committing twice (daemon.md D22). Tests: `publish_conflict_fix_rerun_succeeds_without_duplicates` (daemon) and `publish_conflict_fix_rerun_loop` (cli). SKILL.md "Publish conflict: fix and re-run" is the agent workflow. — Cost if wrong: a batch whose paths were published and then reverted to the base in the workspace counts as landed and is skipped (nothing to commit anyway).

- A write with no daemon listening is `Busy`, `detail.reason = "daemon_down"`, in `strata_daemon::client::call` as in the cli. — cli.md D2 (2026-10-23) rules it explicitly and drops types.md's `ReadOnly` wording for this case; that later, explicit ruling wins over daemon.md §6's table row (which now points to D2). The daemon first shipped `ReadOnly` (merged as 0c59dfb) and was changed on impl/cli. `ReadOnly` `shutting_down` for queued writes at shutdown (daemon D17) is unchanged. — Cost if wrong: a caller branching on `ReadOnly` for "start the daemon" never sees it; it must read `Busy` + `detail.reason`.
