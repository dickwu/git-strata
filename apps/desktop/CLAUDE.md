# apps/desktop

The GIT STRATA desktop app: a Next.js static export inside Tauri 2, built with bun. The repo-root `CLAUDE.md` applies here too.

@AGENTS.md

- **Done bar** (the test steps of `.github/workflows/desktop-pack.yml`, plus lint), from `apps/desktop` after `bun install --frozen-lockfile`:

  ```sh
  bun run check        # tsc --noEmit, then bun test src
  bun run lint         # oxlint src
  cargo test --locked --manifest-path src-tauri/Cargo.toml
  ```

  A change to `scripts/` or to the connector wiring also runs `bash scripts/tests/test-check-release-no-connector.sh` and `bash scripts/tests/test-make-signing-identity.sh`.
- **Lint is oxlint** (`.oxlintrc.json`). The `correctness` category is an error. Eight rules that fire in today's code are held at `warn` there as the baseline, so `bun run lint` exits 0 with warnings: add none, and raise a rule back to an error once its warnings are gone.
- **TypeScript is the native 7.x compiler.** The `typescript` package still ships `tsc`, but its root export no longer carries the classic compiler API (only `typescript/unstable/*` entry points exist), so tools built on that API fail here. That includes ESLint's TypeScript support: typescript-eslint refuses TypeScript 7.0.
- **Separate Cargo workspace.** `src-tauri` has its own `[workspace]` and `Cargo.lock`, so every cargo command takes `--manifest-path` (or runs from `src-tauri`). From the core it depends on `strata-client` and `strata-types` only, never `strata-daemon` (`docs/modules/gui.md` §2.3). When those two crates change their dependencies, this lock needs refreshing too, or `cargo test --locked` fails.
- **The app talks to the live daemon.** The socket path comes from `$HOME` alone, so `bun run tauri:dev` attaches to the user's real daemon. Launch it only when the user asks; verify changes with the tests, which run a fake daemon fed from `src-tauri/tests/fixtures/`.
- **A Tauri command is registered in three places** that a test keeps equal: `APP_COMMANDS` in `src-tauri/build.rs`, `generate_handler!` in `src-tauri/src/lib.rs`, and a kebab-case `allow-` entry in `src-tauri/capabilities/default.json` (`daemon_status` becomes `allow-daemon-status`). The same test hard-codes the command count. `src-tauri/permissions/autogenerated/` is written by tauri-build.
- **Daemon reply shapes are a contract.** `src-tauri/tests/fixtures/p1/` holds the requests the app sends (`requests.json`) and the daemon replies it is built against; the core test `gui_fixtures` checks them against a real daemon. After a deliberate reply change, regenerate them from the repo root with `GUI_FIXTURES=write cargo test -p git-strata --test gui_fixtures` and update `src/lib/types.ts`.
- **`dev-connector` stays out of release builds.** `tauri-plugin-connector` exists only behind the `dev-connector` feature, which the `tauri:dev` script alone enables. `scripts/check-release-no-connector.sh` guards this. Its checks include the feature as a default, a `connector:*` grant in `capabilities/` (rather than `capabilities-dev/`), any script other than `tauri:dev` that enables it, and a null CSP.
- **Static export.** `next.config.ts` sets `output: 'export'` and Tauri loads `dist/`, so nothing runs on a server: Server Actions, request-dependent Route Handlers, cookies and rewrites are unavailable (full list: `node_modules/next/dist/docs/01-app/02-guides/static-exports.md`). The frontend gets its data through the Tauri commands.
- **GUI invariants** G1–G9 are in `docs/modules/gui.md` §4. Among them: the GUI holds nothing that makes the daemon treat an action as confirmed (G1), it opens no file under the data root or a repo (G5), and repo-supplied text renders as plain text under the strict CSP (G6).
